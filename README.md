# Видеоаналитика операционных процессов

Учебный проект по обнаружению видимых признаков сокрытия товара в ритейле. Система должна находить эпизоды на видео, указывать участника и время, сохранять фрагмент для проверки человеком. Помещение предмета в сумку само по себе не доказывает неоплату или кражу.

**Статус HW3.** На 60 контрольных записях с обновлённым селектором бейзлайн доставил в очередь 13/37 событий, MVP — 21/37. На слепой партии ORBIT обе версии пропустили два события. В отчёте собраны результаты экспериментов, а в автономном демо — ролики, окна селектора и сохранённые ответы VLM. [Отчёт ДЗ3](hw_3/README.md) · [Подготовка пилота](docs/ml_system_design_doc.md#3-подготовка-пилота).

## Изменение фокуса после ревью

В первой итерации распознавание `Take / Put / Touch` рассматривалось как основа для поиска эпизодов с товаром. После ревью и обсуждения с руководителем практики фокус уточнили: сотруднику важно находить эпизоды видимого сокрытия, поэтому во второй итерации проверяем этот сценарий напрямую. Обычные действия остаются контекстом и отрицательными примерами. Их распознавание само по себе не подтверждает качество поиска сокрытий. Пункты 1.1–2.2 системного документа уточнены под новую цель; это изменение постановки, а не отчёт о полученном качестве модели.

| Раздел | В предыдущей версии | В текущей версии |
|---|---|---|
| 1.1. Цель и успех | Первый результат — распознавание `Take / Put / Touch` | Поиск и проверка эпизодов сокрытия, качество событий и время проверки |
| 1.2. Требования | Обычные взаимодействия сейчас, сокрытие позже | Сокрытие — основной сценарий MVP; решение проверяет человек |
| 1.3. Скоуп | Сокрытие отложено на следующий этап | Сокрытие включено; взятие, возврат и касание — контекст и обычные действия |
| 1.4. Предпосылки | Акцент на временной модели взаимодействий | VLM как возможный инструмент разметки и распознавания с ручным контролем |
| 2.1. Постановка | Распознавание трёх действий у полки | Обнаружение и временная локализация видимого сокрытия |
| 2.2. Архитектура | Кадровый энкодер с классификатором; планируемая временная RGB-модель | Общий селектор окон, один проход VLM в бейзлайне и условный второй проход в MVP |

## Планируемый результат

- Обработка видеозаписи и выдача событий с участником, временем и основанием сигнала.
- Просмотр фрагмента и оценка пользователя: подтверждение, ошибка или недостаток информации.
- Ручная разметка событий в проверенных клипах. Для подготовки дополнительных примеров предусмотрена предразметка с VLM и проверкой человеком.
- Воспроизводимое сравнение бейзлайна и MVP, отчёт о качестве и затратах.

Основная метрика — полнота очереди сотрудника. На одних и тех же записях измеряем также точность очереди, число ложных подтверждений и нагрузку на проверяющего.
