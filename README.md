# Видеоаналитика операционных процессов

Проект по распознаванию действий людей и взаимодействий с товарами на видео. В текущем сезоне фокус — ритейл: признаки сокрытия товара, порча имущества и ситуации, требующие внимания сотрудника.

Система должна находить наблюдаемые действия, сохранять их временные интервалы и показывать видеофрагменты для проверки. Решение о нарушении принимает человек. Например, помещение предмета в сумку само по себе не доказывает неоплату.

**Статус:** начальное проектирование и подготовка рабочего окружения. В этом репозитории пока нет реализации обработки видео, обученных моделей и результатов экспериментов. Описанные ниже возможности — план разработки.

## Задача проекта

Камеры позволяют восстановить инцидент после его обнаружения, но просмотр большого объёма записей требует времени. Проект переводит работу с видео к поиску конкретных событий: что произошло, где, когда и на каких наблюдениях основан результат.

Пользователи — сотрудники безопасности и операционные руководители магазина. Ожидаемая польза: сократить время поиска и проверки эпизодов, а после проверки качества в потоковом пилоте — помочь своевременно реагировать на инциденты. Снижение потерь предстоит измерить отдельно.

## Первая итерация

Первый измеримый результат — распознавание взаимодействий с полкой на данных **RetailAction**:

| Класс | Наблюдаемое действие |
|---|---|
| `Take` | Покупатель берёт товар |
| `Put` | Покупатель возвращает товар |
| `Touch` | Покупатель касается товара без взятия или возврата |

Для каждого события планируется выдавать класс, интервал времени и доступную локализацию взаимодействия. Эти действия образуют основу для дальнейшего анализа, но сами по себе не создают тревогу о краже.

Первый прикладной триггер следующего этапа — **«Сокрытие товара»**: перемещение товара в карман, сумку, под одежду или другое место сокрытия. Его подключение зависит от наличия подходящих RGB-видео, временной разметки и похожих обычных действий для проверки ошибок. Качество `Take / Put / Touch` не подтверждает качество этого триггера.

## Планируемый результат

- Загрузка видеозаписи, настройка зон интереса и запуск обработки.
- Временная шкала действий; для проверенных рискованных сценариев — отдельная лента инцидентов.
- Карточка события с источником, таймкодом, видеофрагментом и основанием сигнала.
- Оценки пользователя: «подтверждено», «ложное срабатывание», «неясно» и комментарий.
- Выгрузка результатов и воспроизводимый отчёт о качестве каждой версии.

Дальнейшие направления: употребление продукции, порча товаров и оборудования, драки, опасные положения человека, оружие, пересечение границ зон и перекрытие камеры. Потоковая обработка IP-камер, связь событий между камерами и интеграция с КСО относятся к последующим итерациям. Полный перечень и ограничения приведены в [дизайн-документе](docs/ml_system_design_doc.md).

## Подход и оценка качества

Планируемая цепочка: видео → общая детекция и трекинг → последовательности кадров и история взаимодействий → распознавание действий → события и видеофрагменты → проверка человеком. Конкретные модели и прикладной стек ещё не выбраны; первый прототип работает с записями на собственном компьютере или сервере.

Сравниваем бейзлайн с временной моделью на одинаковом разбиении данных. Основные метрики — precision, recall и F1 по каждому типу события. Для непрерывных записей дополнительно измеряем ложные сигналы на камеру в час, задержку и скорость обработки на указанном оборудовании. Подготовленные сегменты RetailAction не заменяют проверку на непрерывном видео. Численные пороги приёмки ещё предстоит согласовать.

LLM рассматривается только для последующих текстовых сводок. Распознавание и базовые описания событий должны работать без него.
